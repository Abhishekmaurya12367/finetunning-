LLM Fine-Tuning with LoRA

A clean, config-driven pipeline to fine-tune an open-source chat LLM on your own dataset using LoRA (Low-Rank Adaptation). No cloud bucket or paid API is required. It runs on a local NVIDIA GPU or on a free Google Colab T4.

The pipeline covers dataset preparation, validation, training, evaluation, and a side-by-side comparison of the base model against the fine-tuned model.

Features
Config-driven: every setting lives in config.yaml, so you run experiments without touching code.
LoRA / QLoRA: train a small adapter instead of the full model, which fits on a 16 GB GPU.
Clean architecture: config loading, training logic, and the entry point are separate modules.
Dataset tooling: convert, split, and validate data before spending GPU time.
Reproducible runs: every run saves its exact config, logs, and metrics.
Base vs tuned comparison: one script prints both models' answers for the same prompts.

How It Works
raw.jsonl
   │  prepare_dataset.py   (convert to chat "messages" format, shuffle, 90/10 split)
   ▼
train.jsonl + validation.jsonl
   │  validate_dataset.py  (check JSON, roles, empty text, example count)
   ▼
finetune.py ─► config.py ─► config.yaml
   │
   ▼
trainer.py → FineTuner.run()
   1. load tokenizer
   2. load base model (fp32 / bf16, or 4-bit for QLoRA)
   3. load dataset
   4. build LoRA config + training args + SFTTrainer
   5. train (only the adapter weights are updated)
   6. evaluate (validation loss and perplexity)
   7. save adapter, logs, metrics, config
   │
   ▼
outputs/lora_adapter/
   │  test_model.py
   ▼
Base model vs tuned model, same prompts

LoRA in one line: the original model weights stay frozen, and small trainable matrices are added to each linear layer. Only those matrices are trained and saved, so training is fast and the output is only a few MB.

Requirements
Python 3.10+
An NVIDIA GPU with 16 GB VRAM or less is fine for the default 1.5B model. Without a local GPU, use Google Colab (free T4).
Linux or Colab is required only if you enable 4-bit mode (bitsandbytes).

Dataset Format

Put your data in data/raw.jsonl, one JSON object per line:

json
{"input": "What is overfitting?", "output": "Overfitting is when a model memorizes the training data and fails to generalize..."}

prepare_dataset.py converts it into the chat format used for training:

json
{"messages": [
  {"role": "user", "content": "What is overfitting?"},
  {"role": "assistant", "content": "Overfitting is when a model memorizes..."}
]}

If your data is already in the Vertex AI contents format, prepare_dataset.py converts that too.

Tips

Aim for 200+ high-quality examples. With fewer than about 50, the tuned model will look almost the same as the base model.
Data quality matters more than any hyperparameter. Fix weak examples before tuning settings.
To train with a system prompt, set SYSTEM_PROMPT in prepare_dataset.py and use the same prompt at inference.
Usage
bash
# 1. Convert raw data and create the train/validation split
python src/prepare_dataset.py

# 2. Validate the dataset
python src/validate_dataset.py

# 3. Fine-tune (reads config.yaml)
python src/finetune.py

#    Or use a different config for an experiment
python src/finetune.py --config my_experiment.yaml

# 4. Compare base vs fine-tuned model
python src/test_model.py

Edit the TEST_PROMPTS list in src/test_model.py with your own prompts before step 4.

Configuration

All settings are in config.yaml.

Section	Key	Description	Default
model	base_model	Hugging Face model ID	Qwen/Qwen2.5-1.5B-Instruct
model	use_4bit	Enable QLoRA (needs bitsandbytes)	false
lora	r	Adapter rank (capacity)	16
lora	alpha	Adapter scaling (commonly 2 × r)	32
lora	dropout	Dropout on adapter layers	0.05
train	epochs	Passes over the training data	3
train	batch_size	Examples per step per device	2
train	grad_accum	Steps before a weight update (effective batch = batch_size × grad_accum)	8
train	learning_rate	Peak learning rate	0.0002
train	max_length	Max tokens per example	1024
train	gradient_checkpointing	Trade speed for lower memory	true
data	train_file, validation_file	Dataset paths	data/*.jsonl
generation	max_new_tokens	Answer length at test time	300
output	output_dir, adapter_name	Where results are saved	outputs, lora_adapter

Unknown keys in config.yaml raise an error, so typos are caught immediately.

Outputs
File	Contents

outputs/train_log.json	Loss at each logging step, useful for plotting a training curve

Loading the tuned model
python
import torch
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

base = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B-Instruct", torch_dtype=torch.float16, device_map="auto"
)
model = PeftModel.from_pretrained(base, "outputs/lora_adapter")
tokenizer = AutoTokenizer.from_pretrained("outputs/lora_adapter")
Troubleshooting
Problem	Fix
No GPU found	Use a CUDA machine or Google Colab with a T4 runtime
CUDA out of memory	Lower max_length (e.g. 512), set use_4bit: true, or switch to Qwen/Qwen2.5-0.5B-Instruct
max_length rejected by SFTConfig	Older TRL versions use max_seq_length. Rename it in trainer.py
bitsandbytes fails on Windows	4-bit mode works on Linux/Colab. On Windows, keep use_4bit: false
Tuned model barely differs from base	Add more and better examples, then raise epochs or r
Validation loss rises while training loss falls	Overfitting. Reduce epochs or add data
Notes on Other Providers
Gemini API / AI Studio: fine-tuning is not available there. Tuning is supported only through Vertex AI, which requires a Google Cloud Storage bucket for the dataset.
OpenAI API: the fine-tuning platform is being wound down and is closed to new users.

That is why this project uses open-source models with LoRA.
